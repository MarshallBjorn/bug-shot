SPR4: Release automation — manifest
=====================================

NEW FILES
---------

.github/workflows/release.yaml
  Glowny pipeline. Trigger: push do main, bez path filtra. Joby: version ->
  guard -> docker-retag / widget-publish -> widget-cdn -> gh-release.
  Retaguje istniejacy SHA-image (docker buildx imagetools create), nie
  rebuilduje. Publikuje @bug-shot/widget do npmjs.org. Wysyla dist widgetu
  na istniejacy CDN (nginx /widgets/) przez istniejacy SSH/WireGuard.
  Tworzy tag vX.Y.Z + GitHub Release jako ostatni krok.

scripts/release/compute-version.sh
  Liczy nastepna wersje z Conventional Commits w zakresie <ostatni tag>..HEAD
  na main. Ignoruje merge commity. Obsluguje feat!:/fix!: oraz "BREAKING
  CHANGE:" w body. Brak release-worthy commitow -> should_release=false,
  exit 0 (sukces, bez release).

scripts/release/release-dry-run.sh
  Lokalny podglad (Git Bash/WSL) — co bylo by opublikowane, zero efektow
  ubocznych. Uzywa compute-version.sh.

scripts/release/render-notes.sh
  Skleja scripts/release/release-notes-template.md z natywnie wygenerowanymi
  przez GitHub API (POST releases/generate-notes) notatkami "What's Changed"
  z linkami do PR.

scripts/release/release-notes-template.md
  Szablon: Docker Images / Widget / Upgrade + placeholder na generated body.
  Sekcja Upgrade opisuje FAKTYCZNY automatyczny deploy (deploy-prod.yaml),
  z odnosnikiem do docs/deployment.md jako fallback DR.

widget/package.json
  NOWY plik. @bug-shot/widget, bez "type": "module" (widget to klasyczny
  browser script, nie ESM). publishConfig.access=public, registry npmjs.org.

widget/scripts/build.mjs
  Deterministyczna konkatenacja (NIE bundler) w kolejnosci zweryfikowanej
  z widget/index.html: vendor/html-to-image.js -> mask.js -> capture.js ->
  widget.js. config.js celowo pominiety (per-srodowisko, w .gitignore).
  Fail-fast jesli brakuje ktoregos pliku wejsciowego.

widget/README.md
  Dokumentacja uzycia (CDN + npm self-hosting) na podstawie faktycznego
  window.BUGSHOT_CONFIG.apiBaseUrl uzywanego w widget.js/mask.js.

RELEASE-AUTOMATION-SETUP.md, RELEASE-AUTOMATION-APPLY.md (ten dokument i ten plik)
  Dokumentacja jednorazowego setupu i procedury zastosowania.

REMOVED BEHAVIOR
-----------------

- deploy-prod.yaml: rebuild obrazu Docker na tag push (docker buildx build
  --push w jobie build-tag-push) — zastapiony retagiem juz istniejacego,
  przeskanowanego SHA-image z release.yaml. Powod: artifact identity —
  obraz wdrazany na prod ma byc bajt-identyczny z obrazem, ktory przeszedl
  Trivy/Dockle w CI (_image.yaml), a nie osobno przebudowanym artefaktem.

- widget.yaml: publikacja do npm.pkg.github.com — zastapiona publikacja do
  publicznego npmjs.org w release.yaml (decyzja z Trello "Publikacja
  widgetu do NPM" + istniejaca dokumentacja projektu wskazujaca publiczny
  @bug-shot/widget).
